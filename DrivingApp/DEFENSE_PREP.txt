POTENTIAL PANEL QUESTIONS & ANSWERS
================================================================================

TECHNICAL QUESTIONS
-------------------

Q1: "What technology stack did you use and why?"

A: We used Laravel 12 (PHP framework) for the backend because it provides
   robust security features, built-in authentication, and follows MVC
   architecture. For the frontend, we used Blade templates with Tailwind CSS
   for responsive design and Alpine.js for interactivity. Our database is
   MySQL for reliable relational data management. We deployed on Railway
   for cloud hosting.


Q2: "How does your role-based access control work?"

A: We implemented Laravel's multi-guard authentication system. Each user type
   (System Admin, School Admin, Instructor, Student) has its own authentication
   guard and model. Middleware checks ensure users can only access their
   authorized routes. For example, an instructor cannot access admin dashboards.


Q3: "How do you ensure data security?"

A: We use password hashing (bcrypt), CSRF protection on all forms, prepared
   statements to prevent SQL injection, and middleware-based route protection.
   We also follow the Data Privacy Act of 2012 by limiting data collection
   to what's necessary.


Q4: "Explain your database design."

A: Our database follows a multi-tenant architecture with school_id as foreign
   keys linking all data to specific schools. Key tables include:
   - schools & school_settings - School configuration
   - admins, instructors, students - User types
   - courses & course_packages - Training offerings
   - time_slots & bookings - Scheduling system
   - progress & payments - Tracking


Q5: "What is the Agile methodology and how did you apply it?"

A: Agile is an iterative development approach. We worked in sprints,
   continuously developing features, testing with users, and refining based
   on feedback. This allowed us to adapt to changing requirements and ensure
   the system meets actual user needs.


FUNCTIONAL QUESTIONS
--------------------

Q6: "Walk us through how a student books a lesson."

A: 1. Student logs in and views available courses
   2. Selects a course and package
   3. Views available time slots with assigned instructors
   4. Books a slot (depending on school settings: auto-assign or choose instructor)
   5. Booking is confirmed or queued for admin approval
   6. Student receives confirmation and can view booking in dashboard


Q7: "How does the instructor assignment work?"

A: School admins can configure two modes:
   - Auto-assign: System automatically assigns available instructors to bookings
   - Student choice: Students can select their preferred instructor when booking
   Instructors are scheduled to specific time slots, and the system prevents
   double-booking.


Q8: "What reports can administrators generate?"

A: Admins can view:
   - Student enrollment statistics
   - Booking and attendance reports
   - Instructor workload summaries
   - Payment/revenue tracking
   - Course popularity metrics


SCOPE & LIMITATIONS QUESTIONS
-----------------------------

Q9: "Why didn't you integrate with LTO?"

A: LTO integration would require government API access and legal agreements
   which are beyond the scope of an academic project. However, our system is
   designed to help students prepare for LTO requirements, and future versions
   could integrate if APIs become available.


Q10: "Why no payment gateway?"

A: Implementing payment gateways like PayMaya or GCash requires business
   registration, merchant accounts, and compliance certifications. For this
   academic project, we focused on core functionality. The system does track
   payments manually, and payment gateway integration can be added in future
   development.


Q11: "You said single-school, but your system supports multiple schools?"

A: Yes! We actually exceeded our original scope. During development, we
   realized a multi-tenant architecture would provide more value, allowing
   the platform to serve multiple driving schools. Each school has isolated
   data and customizable branding.


CONCEPTUAL QUESTIONS
--------------------

Q12: "What is the significance of your study?"

A: Our system benefits:
   - Students: Organized training, easy booking, progress tracking
   - Instructors: Reduced admin work, easy schedule management
   - School Owners: Centralized operations, better efficiency
   - Community: Better trained drivers = safer roads
   - Future Researchers: Reference for similar systems


Q13: "How is your system different from existing solutions like DRIVEHUB?"

A: While DRIVEHUB focuses on a driving school finder with mobile app,
   DriveED Hub focuses on:
   - Multi-tenant SaaS - One platform for many schools
   - School branding - Each school can customize their look
   - Comprehensive CMS - Full content management, not just booking
   - Role-based dashboards - Tailored experience per user type
